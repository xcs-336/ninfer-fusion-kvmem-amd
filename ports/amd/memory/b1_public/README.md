`prepare_public_bf16.py` pins 13 small actual native inputs and calls the frozen
six-case transform in memory without changing it. Its new output directory must
be separate from native production sources. Existing output is accepted only

The generator specializes the actual public wrapper and its actual BF16 small-T,
prompt and append launchers. Validation, route resolver, split/workspace planning,
column offsets, full width, dynamic device `table_rows`, reducer and sigmoid gate
remain. Only non-BF16 launcher branches are removed from this BF16-only candidate;
unsupported public storage is rejected before workspace allocation. Original
BF16 kernel bodies are the same frozen copies with the previously reviewed
plane-table address substitution. Null tables preserve the exact affine address
expression. The new public entry has a distinct symbol name, so existing products
continue to resolve their original implementation.

The finite scope is PageMajor D256, H24/KV4 or H16/KV2, B1, dense BF16, logical
width and visible-key envelope at most 512. Physical groups must cover logical
pages; both plane tables are null or both present. Reject true B>1, valid-column
masks, selected blocks, prototype mask environment settings, quantized planes,
ring/holey history and larger envelopes. The original public cached-only entry
is intentionally not admitted by this append-first product slice. It throws
before allocation. Device positions/table IDs remain the original caller-owned
validity contract: positive live history, contiguous positions, valid minted
group IDs and legal device row. No hidden host readback certifies them.

At this bound the unmodified BF16 resolver never selects ChunkedSmallT: H24's
W9..64 prompt cutoff is 640; H16's W7..12 chunk cutoff is strictly greater than
512 and W13..64 greater than 1024; small-prefill W>=17 needs at least W*64 or
W*80 keys. Wider W takes Prompt. SmallT and Prompt remain data/profile dependent,
not forced by the candidate. The original chunk loop and offset-aware small-T
launcher are nevertheless retained. This fact does not admit larger envelopes.

The new owned fixture has four cases: two head geometries times W3/W35. These
cover actual SmallT and Prompt with the original envelope `{1,512}`. Each case
calls the actual public candidate twice, producing ungated and gated outputs.
The ungated output faces the byte-identical independent FP64 attention oracle
and original `2.8e-3 / 1e-3 / 2/256 max-reference` criterion. Gate uses the
original independent sigmoid criterion `2e-5 + 4.05e-3*abs(reference)` against
the intermediate BF16 output and must be **bit-identical** to the original
`sigmoid_mul` on that same BF16 boundary. The public SmallT fused gate and Prompt
standalone gate therefore meet the same boundary check. This new fixture is not
the full original Attention suite, all widths, rotated Tensor postprocessing or
an Engine qualification.

Each case publishes two real original execution-table rows over minted handles,
with a three-page cyclic permutation. Two independently captured Graphs (one
ungated, one gated) keep the matrix, device row selector, K/V tables and their
own output addresses stable. Each arm's replay sequence is row0/base63,
row1/base(512-W), row0/base63, totaling 24 captured replays over four cases.
Query and gate values also change.
During the middle replay a real typed loan moves live K cells across the original
semantic plane slabs and the raw borrower fills its excluded window with `0xd3`.
Return does not assume identity placement. Both stage-matched affine controls run
only before the loan, after explicitly verifying initial identity placement.

Before every arm replay the actual mapped Core Host-record copy restores all eight
live canonical page records, setting only target append rows to BF16 NaN. The
fixture reads every target row back to prove the poison, poisons both output
payloads and poisons caller partial/scratch payload after checking no workspace
scope is live. Thus the gated arm cannot inherit the preceding arm's valid
partials or appended rows. Each ungated replay first passes its independent
FP64 oracle and preserves a host BF16 checkpoint tagged with this phase. The
separately re-seeded gated replay uses only that already-verified host checkpoint
for its BF16 boundary oracle and standalone split-gate comparison; it never
uses the preceding device partials or output as execution evidence.
Each arm checks every K/V/history byte, every external guard, inputs/matrix,
workspace scope and original capacity, the entire active borrower canary and
the unchanged Graph/table allocation. Thus stale prior output, stale append,
wrong row, wrong affine base and borrower alias cannot silently pass.

The maximum explicit payload is 4 MiB (KV4, 16 groups, two planes); pinned page
records are 2 MiB. Guarded operands, oracle arrays and split scratch are bounded
small fixture allocations, not model weights; a conservative fixture estimate
is 0.125 GiB host before HIP/compiler/module overhead. This estimate is not a
measured memory receipt or authorization to lower root's host/GPU guard floors.
An eventual explicit `--run` requires root's byte0 lock, owned job/PID monitor,
deadline and resource gate. No argument prints PLAN_ONLY and touches no device.
There is no event timing, resource hold, performance claim or automatic test run.
